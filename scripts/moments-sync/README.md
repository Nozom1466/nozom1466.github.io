# 此刻：每 15 分钟静态同步

## 发布路径

手机闪念同步到原 COS 桶；GitHub Actions 在每小时第 7、22、37、52 分钟读取 COS。正常、可解码的记录全部公开，无须标签；已删除、锁定、归档记录不发布，SNENC1 加密记录跳过。读取失败或附件尚未同步完成时，工作流失败并保留上一版站点。

同一个 Hugo 工作流处理定时、手动和 main 分支推送，串行部署，避免旧版博客覆盖新版。定时检查仅在公开内容变化时部署；手动运行和代码推送强制重新构建。首次部署后不需要电脑开机。

Repository secrets 使用 `COS_SECRET_ID` 和 `COS_SECRET_KEY`，对应专用腾讯云子账号的一组长期密钥。只需当前桶的目录列举与对象读取权限；本程序没有 COS 写入、删除或修改权限的操作。桶固定为 `snapnote-test-1316371247`，地域 `ap-shanghai`。不要使用主账号密钥，也不要把凭据写入文件、命令行或网页。

## 数据与成本

原件始终保留在 COS。生成的正文分页 JSON、缩略图和原图展示副本随 GitHub Pages 构建产物发布，**不提交到 Git 仓库**；浏览器访问静态文件，不请求私有桶，不使用长期密钥或会过期的签名链接，也不改变 COS 桶权限。

每次列举笔记目录，存在图片引用时也列举附件目录。缓存命中时只下载 ETag 已变化的正文及图片。缓存不存在或被清理时需要重新下载。缓存 `.moments-cache` 仅保存已允许公开的正文及图片，不保存原始笔记 JSON、设备信息、OCR、隐藏笔记正文或凭据。由于缓存和历史部署可能留有旧副本，删除不是对已公开内容的彻底撤回。

分页为 20 条，网页最多保留 100 条。图片列表使用最长边 384px 的 WebP，原图字节不变。单条笔记上限 2MB，图片上限 25MB，导出数据上限 650MB，超过后停止发布而不静默截断。GitHub Pages 不是无限容量图床，长期增长超过限制时需改用 COS 公开展示目录或其他附件托管方案。

工作流缓存和构建产物有各自额度；Pages 构建产物保留 1 天，公开数据缓存仅变化时保存。定时调度可能延迟；公开仓库长期无活动也可能被 GitHub 暂停定时任务。定期查看 Actions 状态即可，不要将调度视为准点保证。

## 验证与限制

运行 `npm ci --prefix scripts/moments-sync`，再运行 `npm test --prefix scripts/moments-sync` 和 `node scripts/moments-render.test.mjs`。测试使用模拟 COS，不会向真实 COS 写入内容。

正式 `hugo` 构建使用静态数据模式；`hugo server` 保留已有本机实时预览。`cli.mjs` 使用 `MOMENTS_SITE_URL` 核对线上清单，比较真正已发布的版本，而不是把成功缓存误认为部署成功；部署失败后下次检查仍会重试。新增内容可能需要等下次检查、构建及 Pages 缓存刷新后才可见。

当前适配器按对象最新修改时间选取同一 UUID 的笔记版本，识别笔记中的删除/锁定/归档字段。闪念 `index_shards` 中独立删除墓碑以及多设备冲突协议仍未验证，需在首次线上测试中确认手机删除能反映到 COS 笔记文件；不应宣称已实现所有闪念内部同步协议。尚未支持的视频、音频等内容沿用“不支持”提示，不作为图片处理。

本次仅完成本地实现与验证。GitHub secrets 的值无法从仓库读回；是否有效、是否有足够权限，只能在获准推送后首次运行工作流时确认。
